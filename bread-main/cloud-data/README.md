# cloud-data — 微信云开发数据准备

这个目录里的文件**不参与小程序运行**，是给微信云开发建库用的资料与导入模板。

放在这里的目的：等你拿到自己的小程序 AppID、开通云开发后，可以直接照做，
不用再回头去手敲 26 个分类名。

---

## 文件说明

| 文件 | 作用 |
|---|---|
| `01-schema-category.json` | 分类集合（`category`）的字段设计说明 |
| `02-schema-goods.js` | 商品集合（`goods`）的字段设计说明 + 一个完整示例商品 |
| `categories.jsonl` / `categories.json` | **26 个分类的导入模板** |
| `goods-sample.jsonl` / `goods-sample.json` | **5 个测试商品**（先跑通流程用） |
| `banner.jsonl` / `banner.json` | **2 条轮播图** |
| `app-config.jsonl` / `app-config.json` | **3 条店铺配置**（`mallName` 等），可选导入 |
| `goods-real.jsonl` / `goods-real.json` | **真实商品**（由 `tools/build-goods.js` 生成，见 tools/README） |
| `goods-real.source.json` | 真实商品的**人写源文件**（改商品只改这个，再跑脚本） |

> **格式说明**：内容是「每行一条 JSON 记录」（JSONL）。
>
> 每份数据都放了**两个扩展名**的副本：`.jsonl` 与 `.json`，**内容完全相同**，任选其一都能导入：
> - `.json` —— 控制台的导入选择框若按文件类型筛选，**可能只列出 `.json`**；
>   这时就用这份（项目里的 `goods-real.json` 一直就是这么用的）。
> - `.jsonl` —— 原始/生成格式（`tools/*.js` 的产物，便于 diff 与脚本处理）。
>   如果向导里找不到它，也可以在选择框的「文件名」里**直接粘贴完整路径**再回车。
> - ⚠️ 两份是**同一份数据**：改了一处必须同步另一处。
>   `tests/test-cleanup.js` 有一条断言会逐字节比对这两种副本，改漏了会测试变红。
> - 💡 如果你在资源管理器里"看不到某个文件"，**先按 F5 刷新**或换个窗口再确认
>   （2026-10-12 店主就遇到过：窗口没刷新，`banner.jsonl` 其实一直在）。
>
> 集合的完整建库步骤与权限设置见 `docs/云开发初始化清单.md`。

字段设计都是从页面实际读取的字段反推的（见文件内注释），没有凭空造字段。

## 导入分类的操作步骤

> 前提：已注册小程序、开通云开发环境。云开发需要你自己的 AppID。
> 更完整的建库清单（含 7 个集合的权限设置、云函数部署、导入顺序）见 `docs/云开发初始化清单.md`。

1. 用微信开发者工具打开本项目，点顶部「**云开发**」按钮，开通环境
   （可选免费的按量付费套餐，个人也能开）
2. 进入「数据库」→ 点「**+**」新建集合，集合名填 `category`
3. 在 `category` 集合里点「**导入**」
4. 选择本目录的 `categories.json`（内容与 `categories.jsonl` 相同；
   **选择框里只会出现 `.json` 那份**，找不到 `.jsonl` 是正常的）
5. 冲突处理方式选「**insert**」（首次导入，集合为空）
6. 导入完成后检查：应该有 **26 条**记录

导入后可以先不管权限，等接数据时再设：
集合权限建议设为「**所有用户可读，仅创建者可写**」（分类是公开数据）。

## 两个需要你决定的分类

「**推荐**」和「**折扣**」在原项目模板里属于**特殊分类**（带图标、不是普通商品分类）。
本模板里我把它们当普通分类处理了。如果你希望它们像原版那样是固定入口
（比如「推荐」始终排在第一位、「折扣」显示打折商品），那它们**不该放在 category 集合里**，
而应该由前端写死，否则会和真实商品分类混在一起。

「**店内环境**」和「**打包袋**」看起来更像信息展示而不是商品分类：
- 如果下面是商品（比如打包袋要卖钱），就保持为普通分类
- 如果只是展示图片/说明，建议单独做一个入口，不要混在商品分类栏

## 商品数据（goods）

商品**没法用模板批量导入**——每个商品有图片、价格、规格，这些只有你能填。
`02-schema-goods.js` 里给了一个**字段完整的示例商品**（含两组规格：磅数 + 口味），
你可以照它的结构在云数据库里手动加，或者用「导入」功能一次导多个。

⚠️ 特别注意（**2026-02-14 已更正**）：本文档此前写「多规格是当前项目的已知硬伤，
前端 `pages/goods-details/index.js` 只读取 `properties[0]`，数据里存两组规格界面上也只显示第一组」。
**该描述已过期**：前端现已完整支持**多组规格**
（`pages/goods-details/index.js` 的 `buildPropertyGroups` / `buildSku`，界面为多组「单选」标签，
并有 `tests/test-spec.js` 覆盖）。**数据结构无需改动**，按上面的示例结构录入即可。

## 还缺什么

| 缺的东西 | 为什么 |
|---|---|
| 商品图片 | 开发期可先用项目内本地路径（如 `/images/logo@2x.png`）；上线前换成外链 HTTPS 或云存储 |
| 商品数据 | 名称、价格、规格，只有你能提供 |

> 种子数据（分类/5 个测试商品/轮播/店铺配置）已备好，见本目录 `*.jsonl`，
> 可直接在云控制台「导入」，先跑通整条链路再录真实商品。
