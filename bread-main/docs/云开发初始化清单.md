## 二、你需要在微信开发者工具里操作的步骤

### 步骤 1：打开项目并确认 AppID

1. 微信开发者工具 → 导入项目 → 目录选 `bread-main`
2. **AppID 一栏填 `wx5b0e027deafefc01`**（若工具已自动读取 `project.config.json`，确认显示的是这个）
3. 打开后看左下角/详情面板，确认 AppID 正确

> ⚠️ 如果工具提示"该 AppID 与项目配置不一致"，选择**使用 project.config.json 中的 AppID**。

### 步骤 2：确认云开发环境

1. 点顶部工具栏「**云开发**」按钮
2. 进入后在左上角**环境切换**处确认看到 `cloud1-d7g2txuxpf22bb979`
3. 如果没有，点「新建环境」（个人主体可选免费额度套餐）
4. **把环境 ID 与上面核对一致**（代码里写死了这个 ID，不一致就连错环境）

### 步骤 3：创建 7 个集合

云开发控制台 → 数据库 → 集合管理 → 点「**+**」新建，依次创建：

| 集合名 | 权限设置 | 说明 |
|---|---|---|
| `category` | **所有用户可读，仅创建者可写** | 商品分类（公开数据） |
| `goods` | **所有用户可读，仅创建者可写** | 商品（公开数据） |
| `banner` | **所有用户可读，仅创建者可写** | 首页轮播图（公开数据） |
| `app_config` | **所有用户可读，仅创建者可写** | 店铺配置（可选，不建也有默认值） |
| `user` | **仅创建者可读写** | 用户资料，必须按 openid 隔离 |
| `cart` | **仅创建者可读写** | 购物车，必须隔离 |

## 三、预期现象与对应含义（重要）

| 你看到的现象 | 含义 | 怎么办 |
|---|---|---|
| 弹窗/提示「**云函数调用失败：…**」 | 云函数调不通（**没有备用数据源可切**，页面直接报错） | 说明步骤 4 没成功：检查云函数是否部署、环境 ID 是否一致；冒号后的 `errMsg` 是原始报错 |
| 弹窗「**数据库错误**」等业务文案 | 云函数通了，但里面的业务/云库操作失败 | 按提示内容排查（如集合缺失、字段不合法），这与「云函数调用失败」是两回事 |
| 点单页**分类/商品为空** | 集合建了但没导入数据，或集合名拼错 | 回到步骤 3、5 核对 |
| 报错「**collection not exists**」 | 集合没建 | 回到步骤 3 |
| 首页**轮播图不显示** | `banner` 集合为空，或 `picUrl` 路径无效 | 回到步骤 5 |
| 商品图不显示 | `pic` 用的是小程序本地路径 `/images/xxx.png`，开发期正常；上传云存储后才换成 `cloud://` | 见下方「图片问题」 |
| 点「结算」→「**云开发支付尚未接入**」 | **正常现象**：个人主体办不了商户号，支付未接 | 换企业 AppID + 商户号后再接（阶段五） |
| 订单列表里**看不到「完成订单」按钮** | `order_hx_uids` 为空（店主白名单没配） | 见下方「店主白名单」 |

### 图片问题（开发期可忽略）

`goods-sample.jsonl` 与 `banner.jsonl` 里的图片路径是 **小程序本地路径**（如 `/images/logo@2x.png`）。开发期能正常显示，因为它们就在项目 `images/` 目录里。

正式上线前二选一：

| 方案 | 做法 | 换 AppID 时 |
|---|---|---|
| A. 云存储 | 上传图片到云存储 → 把库里的 `pic` 改成 `cloud://cloud1-d7g2txuxpf22bb979.xxx/文件名` | ⚠️ 环境 ID 变了，**引用会失效**，需批量替换 |
| B. **外链 HTTPS（推荐）** | 图片放外部图床/CDN，`pic` 填 `https://...` | ✅ **零改动** |

### 店主白名单（订单列表的「完成订单」按钮）

> 2026-10-10：**扫码核销已整体下线**（「我的」页入口、订单详情二维码、`scan-result` 页面、

要启用：把你的 openid 填进去。

4. **重新部署云函数**（步骤 4）

## 五、换企业 AppID 时要改的地方

> ⚠️ **2026-10-14 更新**：原先这里写的是"只要改 3 处"，**已经过时** ——
> 环境 ID 现在散落在代码、文档、云存储 fileID 前缀、`adminOpenids`、云库记录里，
> 漏一处就会出现"连错环境/图片全裂/店主身份失效"。
> 现在有**专用清单 + 可预演脚本**：
> - 清单：[换新号迁移清单.md](换新号迁移清单.md)（控制台步骤、哪些数据要迁、哪些绝不要迁）
> - 脚本：`node cloud-data/tools/migrate-env.js --to <新环境ID> [--appid <新AppID>] [--apply]`
>   （不加 `--apply` 只预演；只替换环境 ID / appid 两个字符串，可 `git checkout -- .` 回滚）

一次迁移要动的四处，速记版：

| # | 位置 | 改什么 |
|---|---|---|
| 1 | `project.config.json` | `appid` → 新 AppID（脚本 `--appid` 可代改） |
| 2 | `utils/data-source.js` | `cloudEnvId` → 新环境 ID（脚本主体功能） |
| 3 | 云开发控制台 | 在新 AppID 下：建 7 个集合 + 设权限 + 建索引 + 部署云函数 + 建定时触发器 + 云存储权限 |
| 4 | 云库数据 | 导 `category` / `goods` / `banner` / `app_config`；**`user` / `cart` / `order` 不要迁** |

**数据迁移**：见 [换新号迁移清单.md](换新号迁移清单.md) 的「数据迁移」一节。
**⚠️ `user` / `order` 不迁** —— `_openid` 随 AppID 变化而失效，迁过去顾客也看不到自己的订单。
