# 换新号迁移清单（阶段 6：换 AppID + 换云环境）

> 适用时机：新的、具备微信支付资质的 AppID 批下来之后。
> 旧环境：个人测试主体（AppID / 云环境 ID 以 `utils/data-source.js` 的 `cloudEnvId`
> 与 `project.config.json` 的 `appid` 为准，本文不写死 —— 迁移后本文仍是准的）。
> 本清单与脚本都**不依赖具体的新环境 ID**，新号到手时把 ID 填进去即可。

**原则**：阶段 6 **只换主体，不改业务逻辑**。所有业务代码一行都不用动 ——
如果发现某个改动其实是"业务改动"，停下来，放到阶段 9/10/11 去做。

---

## 一、先用脚本扫一遍：环境 ID 到底散落在哪

```bash
cd bread-main
node cloud-data/tools/migrate-env.js --to <新环境ID>          # 预演：只报告，不改文件
node cloud-data/tools/migrate-env.js --to <新环境ID> --appid <新AppID> --apply
```

- **不加 `--apply` 就是预演**（默认安全），会列出「哪个文件、第几行、几处引用」；
- 脚本只替换**环境 ID / appid** 这两个字符串，跳过 `node_modules`、`miniprogram_npm`、
  `.git`、`.trash-cleanup`、`.tools` 与非文本文件；
- 回滚：本仓库在 Git 下，跑完先 `git diff` 复核，要撤销就 `git checkout -- .`；
- 跑完必须 `npm test` 全绿（`tests/test-migrate-env.js` 守着脚本本身的边界）。

> ⚠️ **`audit/` 下的四份审计报告是历史快照，不要改**（里面的旧环境 ID 是"当时的证据"）。
> 需要跟着改的"活文档"是：`docs/云开发初始化清单.md`、`cloud-data/tools/README.md`（脚本会自动改）。
> 另外 `实施步骤清单.md`（在工作区根目录，不在 bread-main 里）有几处环境 ID 记录，
> 迁移时**手工**更新：搜 `cloud1-` 把旧 ID 逐个改（脚本扫不到仓库外层）。

## 二、控制台侧：新号里的操作（脚本碰不到，必须手工）

| # | 步骤 | 注意 |
|---|---|---|
| 1 | 新 AppID 下开通**云开发**，记下新**环境 ID** | 个人主体可选免费额度；企业主体按量付费 |
| 2 | 建 7 个集合：`category` `goods` `banner` `app_config` `user` `cart` `order` | 名字必须完全一致 |
| 3 | 设权限：`category`/`goods`/`banner`/`app_config` = **所有用户可读，仅创建者可写**；`user`/`cart`/`order` = **仅创建者可读写** | ⚠️ 后三个设错 = 顾客之间能互看购物车/订单 |
| 4 | 建索引：`order.orderNumber`（**唯一**）、`order._openid`、`cart._openid`、`goods.categoryId`、`order.clientOrderToken`（普通索引，2026-10-14 下单幂等查重用） | `orderNumber` 唯一索引是防重复单号的最后一道防线；`clientOrderToken` 索引让幂等判重不走全表扫描 |
| 5 | **上传并部署云函数 `api`**（右键 `cloudfunctions/api` → 云端安装依赖） | 不部署 = 全站「云函数调用失败」 |
| 6 | 建**定时触发器**（未支付订单 15 分钟自动取消） | 没建也能跑（读取兜底），但建议建上 |
| 7 | 导入数据（见下一节） | —— |
| 8 | 云存储：新建 `goods/`（轮播图可放 `banner/`），权限 = **所有用户可读**，上传图片 | 权限设成"仅创建者可读写"→ 你自己看得到、**顾客是裂图** |

## 三、数据迁移：哪些要搬、哪些绝对不要搬

```bash
cd bread-main
node cloud-data/tools/build-goods.js        # 确保 goods-real.json(.jsonl) 与源文件一致
```

| 集合 | 迁不迁 | 怎么迁 |
|---|---|---|
| `category` | ✅ 迁 | 控制台 → 导入 `cloud-data/categories.json`（26 条），冲突处理 **insert** |
| `goods` | ✅ 迁 | 导入 `cloud-data/goods-real.json`，冲突处理 **upsert** |
| `banner` | ✅ 迁 | 导入 `cloud-data/banner.json`，**upsert** |
| `app_config` | ✅ 迁 | 导入 `cloud-data/app-config.json`（门店名等）；配送规则若要改数值，另见 `delivery-rule.sample.json` |
| `user` | ❌ **不要迁** | `_openid` 随 AppID 变，迁过去顾客也认不出自己的资料 |
| `cart` | ❌ **不要迁** | 同上，且购物车本来就是临时的 |
| `order` | ❌ **不要迁** | 同理；旧订单留在旧环境里备查（真要留档就导出成文件存着） |

> **配送费规则不用重配**：2026-10-14 起店主给的档位写进了**代码默认值**
> （`config/delivery.js` → 云函数副本 `delivery-config.js`），部署云函数就带着走；
> 云库里的 `delivery_rule` 记录只是"以后改价不用发版"的可选覆盖。

## 四、图片（`cloud://` 前缀会失效）

`cloud://` 的 File ID 里**嵌着环境 ID**，换环境后旧 File ID 全部失效 → 图片全裂。

- 现在（2026-10-14）：商品图与轮播图**还在小程序包内**（`/images/...`），所以这一步**暂时无事可做**；
- 若在迁移前做了 T-1（图片改云存储）：
  1. 把图片重新上传到**新环境**的云存储 `goods/`（轮播图 `banner/`）；
  2. 改 `cloud-data/goods-real.source.json` 顶层的 `imageBase`（换成新环境前缀）；
     轮播图改 `cloud-data/banner.json` + `banner.jsonl` + `handlers.js` 的 `BANNERS`（三处一致）；
  3. 重跑 `build-goods.js` → 重导 `goods` / `banner`；
  4. 再用 `migrate-env.js` 扫一遍（旧前缀在数据文件里会被列出来）。

## 五、迁移后必须人工确认的 4 件事

| # | 确认什么 | 怎么确认 |
|---|---|---|
| 1 | 小程序连的是**新环境** | 开发者工具 → 云开发：环境切换处是新 ID；`utils/data-source.js` 的 `cloudEnvId` 也是 |
| 2 | 首页/点单页有商品（说明库导对了） | 真机预览：分类 26 个、商品 5 个 |
| 3 | 店主身份 | 填 `cloudfunctions/api/shop-config.js` 的 `adminOpenids`（**新号下店主的新 openid**），重新部署；她的「完成订单」按钮应出现（T-2） |
| 4 | 门店坐标与营业时间 | 用「我的 → 校准门店坐标」复核一次（真机），确认导航与"距门店 X 公里"正常 |

## 六、迁移完成后的收尾

1. `git diff` + `npm test` 全绿 → 提交（建议单独一个提交：`chore: 迁移到新 AppID / 新云环境`）；
2. 旧环境**先别删**：留 1–2 周，用于核对历史订单与"新环境是不是漏导了什么"；
3. 更新 `实施步骤清单.md`：阶段 6 勾选、T-1/T-2/T-5/T-6/T-7 的状态、以及"最近更新"日期；
4. 确认**店主端（阶段 10）**在新号下可用：页面与 5 个云函数 action 已随本次迁移一起搬过去
   （代码无需改动），只需做完第 92 行那件事 —— **在新环境下重新取一次她的 openid 填进
   `adminOpenids`**（openid 是"AppID + 微信号"唯一的，旧号的值在新号下无效）。
   她登录一次后，「我的」页在开发版/体验版会显示「复制我的 openid」。
   细节见 `docs/云开发初始化清单.md` 的「店主端（阶段 10）上线前置」（5 件事）。

## 附：常见故障对照

| 现象 | 原因 |
|---|---|
| 页面全部「云函数调用失败」 | 云函数没部署 / 环境 ID 不一致 / 环境过期 |
| 首页有分类、没有商品 | `goods` 没导，或 `categoryId` 与分类 `_id` 不一致 |
| 图片全裂 | 图片在云存储但权限不是"所有用户可读"，或 File ID 还是旧环境前缀 |
| 顾客之间能互看订单 | `user`/`cart`/`order` 权限没设成"仅创建者可读写" |
| 订单号偶发重复 | `order.orderNumber` 唯一索引没建 |
