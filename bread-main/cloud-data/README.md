# cloud-data — 微信云开发数据准备

这个目录里的文件**不参与小程序运行**，是给微信云开发建库用的资料与导入模板。

放在这里的目的：等你拿到自己的小程序 AppID、开通云开发后，可以直接照做，
不用再回头去手敲 26 个分类名。

---

## 文件说明

| 文件 | 作用 |
|---|---|
| `01-schema-category.json` | 分类集合（`category`）的字段设计说明 |
| `02-schema-goods.js` | 商品集合（`goods`）的字段设计说明 + 一个完整示例商品 |
| `categories.jsonl` / `categories.json` | **26 个分类的导入模板** |
| `goods-sample.jsonl` / `goods-sample.json` | **5 个测试商品**（先跑通流程用） |
| `banner.jsonl` / `banner.json` | **2 条轮播图** |
| `app-config.jsonl` / `app-config.json` | **3 条店铺配置**（`mallName` 等），可选导入 |
| `delivery-rule.sample.jsonl` / `.json` | **配送规则模板**（`app_config` 集合里 `key = 'delivery_rule'` 的那条记录）——阶段 8 起运费/外送范围可配，见下方「配送规则怎么改」 |
| `goods-real.jsonl` / `goods-real.json` | **真实商品**（由 `tools/build-goods.js` 生成，见 tools/README） |
| `goods-real.source.json` | 真实商品的**人写源文件**（改商品只改这个，再跑脚本） |

> **格式说明**：内容是「每行一条 JSON 记录」（JSONL）。
>
> 每份数据都放了**两个扩展名**的副本：`.jsonl` 与 `.json`，**内容完全相同**，任选其一都能导入：
> - `.json` —— 控制台的导入选择框若按文件类型筛选，**可能只列出 `.json`**；
>   这时就用这份（项目里的 `goods-real.json` 一直就是这么用的）。
> - `.jsonl` —— 原始/生成格式（`tools/*.js` 的产物，便于 diff 与脚本处理）。
>   如果向导里找不到它，也可以在选择框的「文件名」里**直接粘贴完整路径**再回车。
> - ⚠️ 两份是**同一份数据**：改了一处必须同步另一处。
>   `tests/test-cleanup.js` 有一条断言会逐字节比对这两种副本，改漏了会测试变红。
> - 💡 如果你在资源管理器里"看不到某个文件"，**先按 F5 刷新**或换个窗口再确认
>   （2026-10-12 店主就遇到过：窗口没刷新，`banner.jsonl` 其实一直在）。
>
> 集合的完整建库步骤与权限设置见 `docs/云开发初始化清单.md`。

字段设计都是从页面实际读取的字段反推的（见文件内注释），没有凭空造字段。

## 导入分类的操作步骤

> 前提：已注册小程序、开通云开发环境。云开发需要你自己的 AppID。
> 更完整的建库清单（含 7 个集合的权限设置、云函数部署、导入顺序）见 `docs/云开发初始化清单.md`。

1. 用微信开发者工具打开本项目，点顶部「**云开发**」按钮，开通环境
   （可选免费的按量付费套餐，个人也能开）
2. 进入「数据库」→ 点「**+**」新建集合，集合名填 `category`
3. 在 `category` 集合里点「**导入**」
4. 选择本目录的 `categories.json`（内容与 `categories.jsonl` 相同；
   **选择框里只会出现 `.json` 那份**，找不到 `.jsonl` 是正常的）
5. 冲突处理方式选「**insert**」（首次导入，集合为空）
6. 导入完成后检查：应该有 **26 条**记录

导入后可以先不管权限，等接数据时再设：
集合权限建议设为「**所有用户可读，仅创建者可写**」（分类是公开数据）。

## 两个需要你决定的分类

「**推荐**」和「**折扣**」在原项目模板里属于**特殊分类**（带图标、不是普通商品分类）。
本模板里我把它们当普通分类处理了。如果你希望它们像原版那样是固定入口
（比如「推荐」始终排在第一位、「折扣」显示打折商品），那它们**不该放在 category 集合里**，
而应该由前端写死，否则会和真实商品分类混在一起。

「**店内环境**」和「**打包袋**」看起来更像信息展示而不是商品分类：
- 如果下面是商品（比如打包袋要卖钱），就保持为普通分类
- 如果只是展示图片/说明，建议单独做一个入口，不要混在商品分类栏

## 配送规则怎么改（阶段 8 起，店主 10-12 反馈 R-03 / R-05）

以前运费与"送多远"是**写死在代码里**的（`config/delivery.js`），店主改不了，也答不上
"只送几公里、哪些小区不送"。阶段 8 把它们搬到云库：

```
app_config 集合
  └─ key = 'delivery_rule'   value = { area: {...}, distance: {...}, freight: {...}, cake: {...} }
```

- **取不到 / 字段写错 → 逐项回退代码默认值**（`config/delivery.js`），不会因为配置读不到就算错钱；
- 前端和服务端**用同一份规则**：`appConfig` action 会把完整规则下发给前端，
  结算页据此显示运费 —— 这是"屏显运费 == 实付"的前提；
- 云函数 `api` 每次外送下单都会重新读一次云库规则（改完**不需要重新部署云函数**）；
  但**前端显示**用的是启动时下发的那份，所以店主改完要让顾客**重新进入小程序**才生效。

> 💡 2026-10-14 起，店主确认的档位**同时写进了代码默认值**（`config/delivery.js` 的 `freight.tiers`），
> 所以**不导入下面这条记录也是准的**；这条记录的价值是"**以后改价不用发版**"——
> 在控制台改一条记录、顾客重新进小程序就生效。（阶段 10 的店主端会把这个编辑做成界面。）

### 字段一览（只写想改的部分即可，其余自动用默认值）

| 字段 | 含义 | 例子 |
|---|---|---|
| `area.excludeKeywords` | **不送区域**命中即拒（优先级高于 `keywords` 白名单） | `["某某花园","某某路"]` |
| `area.forbidBeyondKm` | **外送距离上限**（公里），超了直接不许外送；`null` = 不启用 | `5` |
| `area.excludedTip` | 命中不送区域时的提示（要给出"可自提"这类替代方案） | `"该小区暂不支持外送，可改自提"` |
| `area.beyondLimitTip` | 超过距离上限时的提示 | `"超出外送范围，可改自提或联系我们"` |
| `freight.tiers` | **距离阶梯**（真正的计费依据），按 `maxKm` 升序匹配第一条 `距离 <= maxKm` 的档 | 见下 |
| `cake.enabled` / `cake.freeWithinKm` | 「6 寸及以上蛋糕 N 公里内免配送费」 | `true` / `3` |

`tiers` 每一项：`{ maxKm, fee, freeAmount, tip }`
- `maxKm`：该档上限（公里，**含等号**）；`null` = "以上全部"，必须放最后一条；
- `fee`：该档运费；`null` = **运费待确认**（不显示具体数字，由店里人工确认）；
- `freeAmount`：该档免运费门槛（元）；`null` = 该档不设免运费；
- `tip`：`fee` 为 `null` 时给顾客看的文案（收得到运费的档位写空串 `""`）。

### 当前生效的规则（店主 2026-10-14 确认）

| 距离 | 运费 |
|---|---|
| 0–3 公里 | 满 **35 元免运费**，不满 35 元收 **5 元** |
| 3–5 公里 | **10 元**（不设免运费门槛） |
| 5–8 公里 | **18 元**（不设免运费门槛） |
| 8 公里以上 | **她打电话跟顾客沟通** → 显示"运费待确认"，不拒绝下单 |
| 任意距离 | **6 寸及以上蛋糕：3 公里以内免配送费** |

> 配送范围由**文字关键词**决定（收货地址里含"太平新城"才送，见 `config/delivery.js` 的 `area.keywords`）；
> 距离只影响运费。店主已明确"整个太平新城都送、片区外不送"，所以 `excludeKeywords` 保持为空、
> `forbidBeyondKm` 不启用。

### 两个例子

```jsonc
// ① 当前生效的规则（= cloud-data/delivery-rule.sample.json，导入它不会改变任何东西）
{"key":"delivery_rule","value":{"freight":{"tiers":[
  {"maxKm":3,"fee":5,"freeAmount":35,"tip":""},
  {"maxKm":5,"fee":10,"freeAmount":null,"tip":""},
  {"maxKm":8,"fee":18,"freeAmount":null,"tip":""},
  {"maxKm":null,"fee":null,"freeAmount":null,"tip":"超出8公里，下单后商家会电话与您确认运费"}
]}}}

// ② 调整示例：改价 + 指定某某花园不送 + 超过 6 公里不接单
{"key":"delivery_rule","value":{
  "area":{"excludeKeywords":["某某花园"],"forbidBeyondKm":6},
  "freight":{"tiers":[
    {"maxKm":3,"fee":8,"freeAmount":50,"tip":""},
    {"maxKm":6,"fee":12,"freeAmount":null,"tip":""},
    {"maxKm":null,"fee":null,"freeAmount":null,"tip":"超出6公里，下单后商家会电话与您确认运费"}
  ]}
}}
```

> ⚠️ `delivery-rule.sample.jsonl` / `.json` 与**代码默认值保持同形**，
> `tests/test-delivery.js` 会逐条比对（模板与代码说的不是一回事就会红）。
> 所以改完**代码默认值**（`config/delivery.js`）后，记得同步这两个模板文件。

### 怎么导入

1. 云开发控制台 → 数据库 → 新建集合 `app_config`（若还没有）
2. 把 `delivery-rule.sample.json` 复制一份、按上表改成店主给的规则
3. `app_config` 集合 → **导入** → 选改好的文件 → 冲突处理选 **upsert**
   （`upsert` 会按 `key` 更新同一条记录，反复导入不会产生重复）
4. 真机验证：**换一个微信号**，用"3km 内不满 35 元""3–5 公里""5–8 公里""8 公里以外"
   各下一单，确认**页面显示的运费 == 下单后订单里的运费**
5. 导入后顾客**重新进入小程序**才生效（规则是启动时下发的）

> ⚠️ 改规则前必须先在代码里跑一遍：`cd bread-main && npm test`
> （`tests/test-delivery.js` 会检验阶梯边界、黑名单优先级、距离上限，以及两端副本是否一致）。

## 商品数据（goods）

> ⚠️ **本店没有"库存"这个概念**（阶段二 2026-10-09 已整体删除）：蛋糕现做，
> 缺货靠「提前 3 小时预订」的规则解决，**不要**再加 `stores` / 限量 / 售罄字段
> （购物车里限制的「单次最多 99 件」是防拆单，不是库存）。

商品**没法用模板批量导入**——每个商品有图片、价格、规格，这些只有你能填。
`02-schema-goods.js` 里给了一个**字段完整的示例商品**（含两组规格：磅数 + 口味），
你可以照它的结构在云数据库里手动加，或者用「导入」功能一次导多个。

⚠️ 特别注意（**2026-02-14 已更正**）：本文档此前写「多规格是当前项目的已知硬伤，
前端 `pages/goods-details/index.js` 只读取 `properties[0]`，数据里存两组规格界面上也只显示第一组」。
**该描述已过期**：前端现已完整支持**多组规格**
（`pages/goods-details/index.js` 的 `buildPropertyGroups` / `buildSku`，界面为多组「单选」标签，
并有 `tests/test-spec.js` 覆盖）。**数据结构无需改动**，按上面的示例结构录入即可。
